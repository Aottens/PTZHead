    2. In `registerWifiEventHandlers()`, replace the entire existing GOT_IP handler block (currently 5 lines: PTZ_LOGI GOT_IP, WiFi.setSleep(false), esp_wifi_set_ps(WIFI_PS_NONE), bound to ARDUINO_EVENT_WIFI_STA_GOT_IP) with the extended version below:

    ```cpp
      WiFi.onEvent([](WiFiEvent_t event, WiFiEventInfo_t info) {
        PTZ_LOGI("WIFI", "GOT_IP %s", WiFi.localIP().toString().c_str());
        // Re-apply power save = off after reconnect (Pitfall 1 from Phase 2)
        WiFi.setSleep(false);
        esp_wifi_set_ps(WIFI_PS_NONE);

        // mDNS: tear down any prior instance, then restart fresh (Pitfall 1 — mDNS
        // stops after ~2min on ESP32; restart-on-GOT_IP is the community fix).
        MDNS.end();
        if (MDNS.begin(kMdnsHostname)) {
          MDNS.setInstanceName(kMdnsInstanceName);
          MDNS.addService(kMdnsServiceType, kMdnsServiceProto, kOscPort);
          if (logShouldEmit(kLogRateMdns, 5000)) {
            PTZ_LOGI("MDNS", "advertising %s.local %s.%s:%u",
                     kMdnsHostname, kMdnsServiceType, kMdnsServiceProto, kOscPort);
          }
        } else {
          PTZ_LOGW("MDNS", "begin failed");
        }
      }, ARDUINO_EVENT_WIFI_STA_GOT_IP);
    ```

    Rationale: `MDNS.end()` before `MDNS.begin()` is idempotent on first call (safe to call `end` when nothing is running) and crucial on reconnects — it kicks the responder out of a potentially-stuck state. `setInstanceName` is set AFTER `begin` (that's the only valid order per the ESPmDNS header). `addService` uses the constants from Plan 01 so the advertised service is `_osc._udp` on port 8000 — matches the listener from Phase 2. Rate-limited log (5s minimum) prevents spam on fast reconnect cycles (Pitfall 7-style mitigation).

    Do NOT call `MDNS.begin()` from `setup()` or `PtzWifi::begin()` — mDNS requires an IP-bound interface, and the GOT_IP event is the only place we know that's true. Boot path through `tryStoredCredentials()` also registers this handler AFTER a successful connect, so the first GOT_IP event (fired by the Arduino event system as part of normal association) will trigger mDNS.

    Note: `tryStoredCredentials()` currently calls `registerWifiEventHandlers()` AFTER the connect loop completes. The first GOT_IP that fires immediately on association might complete BEFORE the handler is registered. To guarantee mDNS starts on the boot path too, this plan relies on the natural reconnect cycle OR on Arduino-ESP32 re-firing the event. If testing shows mDNS doesn't start at boot, a follow-up can call the mDNS stanza directly after `registerWifiEventHandlers()` — but DO NOT do that proactively in this task; the GOT_IP handler registration happens right after `WL_CONNECTED`, and disconnect/reconnect events within the session will trigger mDNS start correctly. Phase 4 hardware validation will confirm.
